# Personal AI Employee - Project Context

## Project Overview
Building a "Digital FTE" (Full-Time Equivalent) - an autonomous AI agent that manages personal and business affairs 24/7 using Claude Code as the reasoning engine and Obsidian as the management dashboard.

**Tagline:** *Your life and business on autopilot. Local-first, agent-driven, human-in-the-loop.*

## Architecture Components

### 1. The Brain
- **Claude Code** - Primary reasoning engine
- Runs in Ralph Wiggum loop for autonomous multi-step task completion

### 2. The Memory/GUI
- **Obsidian Vault** - Local Markdown knowledge base
- Key files:
  - `Dashboard.md` - Real-time summary
  - `Company_Handbook.md` - Rules of engagement
  - `Business_Goals.md` - Objectives and metrics
  - `/Inbox`, `/Needs_Action`, `/Done` folders

### 3. The Senses (Watchers)
- **Gmail Watcher** - Monitors email for urgent messages
- **WhatsApp Watcher** - Detects keywords (urgent, invoice, payment)
- **File System Watcher** - Monitors drop folders
- **Finance Watcher** - Tracks bank transactions

### 4. The Hands (MCP Servers)
- **Email MCP** - Send/draft emails
- **Browser MCP** - Web automation for payments
- **Calendar MCP** - Scheduling
- **Odoo MCP** - Accounting integration (Gold/Platinum tier)

### 5. Orchestration
- **Orchestrator.py** - Master process for scheduling and folder watching
- **Watchdog.py** - Health monitoring and process restart
- **Process Manager** - PM2 or supervisord for daemon management

## Key Patterns

### Ralph Wiggum Loop
Stop hook pattern that keeps Claude iterating until tasks are complete:
1. Orchestrator creates state file with prompt
2. Claude works on task
3. Stop hook checks if task is in /Done
4. If not complete, re-inject prompt and continue

### Human-in-the-Loop (HITL)
For sensitive actions (payments, new recipients):
1. Claude creates approval request file in `/Pending_Approval/`
2. Human reviews and moves to `/Approved/` or `/Rejected/`
3. Orchestrator triggers MCP action only after approval

### Watcher Pattern
```python
class BaseWatcher:
    - check_for_updates() -> list
    - create_action_file(item) -> Path
    - run() - infinite loop with error handling
```

### Claim-by-Move Rule (Multi-Agent)
First agent to move item from `/Needs_Action/` to `/In_Progress/<agent>/` owns it

## Security Principles
- **Never store credentials** in vault or code
- Use environment variables (.env, never committed)
- Implement dry-run mode for development
- Audit logging for all actions
- Rate limiting on external actions

### Permission Boundaries
| Action | Auto-Approve | Require Approval |
|--------|-------------|------------------|
| Email replies | Known contacts | New contacts, bulk |
| Payments | < $50 recurring | New payees, > $100 |
| Social media | Scheduled posts | Replies, DMs |
| File operations | Create, read | Delete, move outside |

## Ethics & Responsible Automation
**AI should NOT act autonomously on:**
- Emotional contexts (condolences, conflicts)
- Legal matters (contracts, filings)
- Medical decisions
- Financial edge cases
- Irreversible actions

**Oversight Schedule:**
- Daily: 2-minute dashboard check
- Weekly: 15-minute action log review
- Monthly: 1-hour comprehensive audit
- Quarterly: Full security review
